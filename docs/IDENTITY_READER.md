# 身份证读取模块

## 当前能力

登记流程通过 `frontend/src/identity-reader.ts` 的 `IdentityReader` 接口读取资料：

```typescript
interface IdentityReader {
  read(): Promise<IdentityCard>;
}
```

`IdentityCard` 包含姓名、性别、出生日期、身份证号、民族和地址。界面调用的是接口，不依赖某个设备型号。

- `identityReader`：真实设备适配器入口。当前明确提示“身份证读卡器尚未接入，请手工填写人员资料”，不会伪装读取成功。
- `simulatedIdentityReader`：返回固定软件测试资料，姓名为“模拟读卡验收（虚构）”，证件号码使用无效行政区划前缀，地址也明确虚构。界面标明模拟资料。模拟不是实体身份证读取能力。
- 手工录入：设备未接入、失败或未带证件时仍可登记。没有证件时应先搜索已有档案；系统不能仅凭同名确认是同一个人。

读取资料后，前端通过受保护的 `POST /api/patients/lookup-identity` 精确匹配。证件不放在 URL 中。已有人员使用服务器档案，并显示历史入口；确认登记时后端再次核对，浏览器提供的资料不能绕过身份一致性、版本、角色及输入校验。

## 接入真实设备

确定型号后，保留 `IdentityReader` 接口及登记页面，在 `identityReader.read()` 适配厂商提供的读取方法，将输出转换为 `IdentityCard`。厂商 SDK、驱动、设备连接方式和旧电脑兼容性需要真机验收；目前没有安装读卡器驱动或本地服务。

系统不假设 Windows 7 浏览器支持 WebUSB，也不要求客户端安装 Python、Node.js 或数据库。若所选设备必须依赖厂商驱动或本地读取桥接程序，具体安装范围应在选型时确认。人员匹配、数据保存、体检编号及历史记录仍由服务器处理。

真实读取失败应抛出可理解的错误，并保留手工录入入口。适配器不得向控制台、运行日志或外部服务输出完整身份证号、地址或身份证照片。

## 隐私与一致性

身份证号、民族和地址只用于获授权的人员登记和档案页面，不加入普通体检列表或报告响应。测试只使用虚构数据；真实身份证信息不得进入测试文件。已有档案不会因为再次刷卡被静默覆盖，资料变更通过档案编辑入口核对并保存。

登记请求结果尚未确认时，原人员资料和本次体检保持锁定，使用同一请求编号重试核对，不能通过重新读卡切换为另一个人。
