# 第 5 阶段：受检者管理

## 范围与停止条件

开始条件：第 1～4 阶段已通过验收，用户授权继续当前阶段。开发目标为受检者新增、详情、编辑、搜索、服务端分页及历史体检入口。本阶段完成后停止，第 6 阶段为体检登记。

现有架构适合一台 Windows 服务器供多台浏览器使用：FastAPI 提供 `/api` 和构建后的 React 网页，SQLAlchemy 仅在服务器连接数据库，资料、报告和备份均保存在服务器。浏览器不连接数据库，不安装 Python、Node.js、PostgreSQL 或桌面客户端。当前本机演示只监听 `127.0.0.1:8000`；实际固定 IP、防火墙、HTTPS、Windows 服务和 PostgreSQL 上线验收另行执行。

## 验收标准

| 项目 | 要求 |
| --- | --- |
| 新增与输入校验 | 管理员、登记员可新增；姓名及性别必填，其余资料选填；非法出生日期、证件号格式及重复有效证件号拒绝 |
| 详情与编辑 | 所列字段完整显示，编辑成功后版本、更新时间更新，服务器提交成功后才提示成功 |
| 搜索与分页 | 姓名、手机号、身份证号由服务器搜索；默认每页 20，最多 100；历史按受检者 ID 分页 |
| 年龄 | 服务端按中国当前日期及生日计算；未填生日显示未知，不保存手工年龄 |
| 权限 | 管理员、登记员可访问档案；科室医生、总检医生及匿名用户不能访问完整档案接口 |
| 持久与快照 | 迁移保护旧数据；已提交资料重启后保留；档案编辑不覆盖体检或报告的历史快照 |
| 并发与失败 | 旧版本拒绝覆盖；失败保留页面输入；编辑、归档、创建体检共用数据库写锁；资料与审计一起提交或回滚 |
| 安全与回归 | 身份证、单位、备注不进入体检及报告响应；新增/编辑审计仅字段名、版本；已有登录、权限、备份测试继续通过 |

归档原因存放在受保护的操作审计表中，便于追溯；普通运行日志不记录原因或档案字段值。已有有效体检的档案禁止归档，软删除保留数据库记录。

## 实际结果（2026-10-02）

【阶段状态】已完成。本轮停在第 5 阶段，没有进入第 6 阶段开发。

【完成内容】前后端支持七项可编辑资料及服务端年龄、创建时间、更新时间、版本；详情页面按需加载，列表及历史默认 20 条。受检者接口独立成模块，沿用单台服务器架构和现有认证。

【验收结果】

| 用户要求的关键标准 | 实际结果 |
| --- | --- |

| 查询详情 | 通过：详情包含全部档案字段及创建、更新时间，错误时有重试入口 |
| 按姓名搜索 | 通过：专项测试及运行服务器 API 查询 |

| 服务端分页 | 通过：接口按 offset/limit 返回当前页；分页测试无重复记录，超过 100 条参数返回 422 |

## 【我如何人工验收】

在演示系统登录管理员或登记员，点击“受检者登记”，在左侧“新受检者”填写虚构资料，点击“登记并选择套餐”。关闭套餐窗口后，从右侧列表搜索资料，点击“查看档案”→“编辑资料”，修改后保存，再重新打开核对；右侧历史区显示对应体检。

如果两个页面同时编辑，后保存的旧版本应显示冲突并保留输入；读取最新资料、核对后才可重新提交。断网时保存应提示数据尚未保存，恢复连接后核对再重试。
